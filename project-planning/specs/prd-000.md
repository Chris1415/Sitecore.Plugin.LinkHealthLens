## 1. Executive Summary

**Link Health Lens** is a custom Sitecore Marketplace app that lives in the SitecoreAI Page Builder
**context panel** and gives an editor a pre-publish glance at the **internal link integrity** of the
page they are editing. It answers one question before the publish button gets pressed: *do the links
on this page point at content that actually exists and is actually live?*

It is **not a broken-link checker and must never present itself as one.** The app runs under the
Marketplace **Mode A** auth model — plain client-side, inside a sandboxed iframe where every call is
brokered by the portal — so it structurally cannot issue a request to an arbitrary origin. External
**reachability** (4xx/5xx, redirect chains, DNS failure) is therefore **permanently out of scope**,
not deferred (ledger Q5). What it ships instead is five checks it can perform honestly and offline:
internal link existence in the CM, links aimed at staged-but-unpublished pages, `http://` scheme
detection, malformed or empty `href`, and in-page anchors whose target is missing from the page's own
HTML. Two of those five are pure string inspection and therefore run on **every** link, external ones
included: *not checked* means **reachability** not checked — never *unexamined* (ledger Q1).

Scope is the **rendered** page including nav and footer chrome. A link's `origin` is **structural** —
decided by where the anchor sits, never by whether attribution succeeded — and each outcome gets its
own honest label, so a body link whose owning field could not be identified is never described as
site chrome (ledger Q2).

### Problem (one short paragraph)

An editor working in SitecoreAI Page Builder has no way to see, before publishing, whether the links
on the page point at content that exists in the CM and is actually published. Bad internal links are
discovered after go-live, by visitors. The signal exists in the tenant — the editor just has no
surface that shows it next to the page they are editing.

### Goal (one short paragraph)

Ship a read-only Marketplace context-panel app that, on every page selection in Page Builder, lists
every link in the rendered page and classifies each one against five internal-integrity checks, with
an **owner-and-open** control where the link can be attributed — it names the owning rendering and
datasource and navigates to that ITEM — and an honest label, one of two, where it cannot.

### Non-negotiables (bullets)

- **There is NO field-level selection (ADR-0010, probe-verified at runtime).** The client exposes
  exactly `["pages.reloadCanvas", "pages.context"]` for mutation and `getValue` is not implemented.
  Navigate to the owning ITEM via `client.mutate('pages.context', { itemId })` and **never label it a
  jump to a field**. No control may promise a resolution the platform cannot perform.

- **Mode A (plain client-side) only.** No backing route, no server-side surface, no OAuth proxy — not
  now, not later. Scaffold via the pack-resolved command
  `npx shadcn@latest add https://blok.sitecore.com/r/marketplace/next/quickstart-with-client-side-xmc.json`
  (cited from the pack brief; do not substitute a Mode B quickstart).
- **No outbound network request to any link target, ever.** Every check is CM-data or static-string
  based. A `fetch`/`HEAD` against a link href is an automatic Critical at code review.
- **"Not checked" means REACHABILITY not checked.** The `http:`-scheme and malformed-href checks are
  string inspection and **do** run on external links. Short-circuiting on `scope === 'external'` and
  skipping them is a defect, not an optimisation.
- **`status` is a SET, not a single value.** One row per anchor, always; multiple statuses coexist on
  that row (an external row may be `insecure-scheme` **and** carry the standing
  *reachability not checked* note). Display precedence is defined in the full PRD § 10.
- **`origin` is STRUCTURAL.** A link is `content` or `chrome` by **where the anchor sits in the
  page**, decided before and independently of attribution. Attribution failing never changes
  `origin`. Three affordances, not two: an owner-and-open control · `in your content — field not identified` ·
  `site chrome — not editable from this page`. Applying the chrome string to a `content` link is a
  false statement about the product and an automatic Critical.
- **The UI must never use the words "broken", "dead", "404" or "unreachable" — anywhere, about any
  link.** The ban is **global**, not external-only: M5 greps for the word, and grep can find a word
  but not what it was applied to.
- **Read-only.** The app performs no write, mutation or publish against the tenant.
- **No persistence.** Findings are computed per page-selection event and held in memory only; no
  storage, no cache that survives a reload, no telemetry.
- Exact label strings, fixed and not copy suggestions: `site chrome — not editable from this page`
  and `in your content — field not identified`.
- SDK request/response shapes are **derived from `node_modules` `.d.ts`** (rule `40`) and cited inline.
  Nothing is scaffolded yet, so every shape below is **unverified** and gets captured in **T0**.

### In scope / out of scope (very short)

- **In scope:** the rendered page in the Page Builder canvas, including nav/footer chrome. Five
  checks — (1) internal link target exists in CM, (2) target exists but is unpublished, (3) `http://`
  scheme, (4) malformed/empty `href`, (5) in-page anchor with no matching target in the page's own
  HTML. Checks 3 and 4 run on external links too. Internal-vs-external classification from the
  href SHAPE (relative = internal, absolute = external — the tenant's host list is EMPTY, ADR-0009).
  Structural `origin` + best-effort owner attribution + owner-and-open control. Two
  divergent panel designs at `/design`, one POC winner.
- **Out of scope:** every outbound network check (4xx/5xx, redirect chains, DNS, mixed-content-by-
  response) — permanent, not deferred. Full attribution for every chrome link. Any HEAD-proxy
  concurrency or rate-limit policy (there is no proxy). Site-wide or multi-page scanning. Any write
  to the tenant. Public Marketplace listing / submission.

### Success criteria (3–7 bullets)

- Page-selection event to complete finding list: **worst observed ≤ 6s** across a named sample of
  **≥ 5 pages**, each ≤ 150 anchors. (Worst-observed, not p50/p95 — a smoke over one or two pages
  cannot produce a percentile.)
- Every anchor present in the page HTML appears in the panel exactly once, matched by
  `href` + document ordinal, **pairwise against an independent DOM query in the canvas** — never
  against the extractor's own output, and **a matching total count is not a reconciliation**.
- ≥ 50% of **structurally-`content`** links carry a working **owner-and-open** control (Assumption
  A3's threshold; the control opens the owning ITEM — field-level selection does not exist, ADR-0010). Because `origin` is structural, the denominator does not shrink when attribution fails.
- The **T2** real-tenant smoke runs against **both** a named known-bad page and a **named known-good
  control page**, and reports zero findings on the control. A uniform-failure sweep proves nothing.
- Zero occurrences of "broken" / "dead" / "404" / "unreachable" anywhere in shipped UI copy
  (grep-able at `/code-review`).

### Key constraints & assumptions

- **Mode A is architectural and load-bearing** — it is what removes external reachability checking.
  ADR-0002; do not re-open it in implementation.
- **Settled before `/architect`, not before `/implement` (ledger Q3):** a **named tenant**, a fixed
  tenant-facing **`app_name`**, completed **operator-guided App Studio registration**, and a **named
  known-bad page plus a named known-good control page**. T0 cannot start without all four.
- **A1 (assumption):** the page-HTML endpoint returns *rendered HTML*, not layout JSON. If it returns
  layout, the casualties are wider than "T1 becomes different work": the `href` + document-ordinal
  row identity loses its source, the in-page-anchor check becomes impossible, M2 is unmeasurable, and
  the chrome half of the rendered scope disappears. Probe first (T0).
- **A2 (assumption):** `path-by-url` can distinguish *page missing* from *page exists but
  unpublished*. This is a headline feature and nothing confirms the endpoint separates them. Probe
  first (T0); do not build the unpublished check on an unconfirmed distinction.
- **A3 (assumption):** content links attribute to an owning datasource often enough that
  "best-effort" reads as partial rather than blank. Below ~50% the feature reads as broken.
- **A4 (assumption):** the page-HTML payload exposes a **structural** signal sufficient to separate
  chrome from page content. `origin` and the three-way label rest entirely on it. If it does not
  exist, the third label has no basis and the chrome/content split must be re-decided mid-build.
  Probe question (f) in T0.
- **Five SDK surfaces, all unverified:** `pages.context` (subscribe) · the page-HTML endpoint
  (`xmc.pages.*` **or** `xmc.agent.*` — which one is itself unresolved) · `path-by-url` ·
  `xmc.sites.*` (hosts) · `application.context`. Capture real shapes + fixtures in **T0**.
- **Sibling reference is `cite-required`:** `quickcopy`, `component-usage-atlas` and `pageshot` each
  solved part of the context-panel problem. Borrowing is allowed; every borrowed pattern is logged in
  `docs/build-decisions.md` with the sibling and file it came from.

## 2. Problem Statement

Editors publish pages with internal links that point at nothing. The target item was renamed, moved,
never created, or — most commonly and most invisibly — **created but never published**, so the link
works perfectly for the editor previewing it and 404s for the visitor. The information needed to
catch all of this already lives in the tenant, but the editor has no surface that shows it beside the
page they are editing. The check happens after go-live, by a visitor, or not at all.

**What this app deliberately does not solve.** The original framing was external link rot — "angry
visitors hitting dead outbound links". Mode A (ledger Q4) makes that structurally impossible: inside
the sandboxed iframe every call is portal-brokered, so the app cannot request an arbitrary origin.
Rather than carry a promise the architecture cannot keep, the problem was **rewritten** in ledger Q5
to the half the app can deliver: internal link integrity, checked against the CM, with no network
request to any link target. What survives for external links is the **string** half — scheme and
malformed `href` — which needs no network at all.

This constraint is stated up front and repeated in the UI because the failure mode is not a missing
feature — it is a **false sense of coverage**. An editor who believes the panel checked their
outbound links, and it did not, is worse off than an editor with no panel at all. The same principle
governs every label in § 6: a confident false statement is the defect, whatever it is about.

## 3. Goals and Success Metrics

**Goals**

- **G1** — Let an editor see, without leaving Page Builder, whether the internal links on the current
  page resolve to real, published content.
- **G2** — Make the boundary of the check obvious, so nobody infers reachability coverage that does
  not exist.
- **G3** — Where a finding is fixable from this page, take the editor to the field; where it is not,
  say plainly *why* instead of offering a dead affordance.

**Success metrics**

| # | Metric | Target | Measured at |
|---|--------|--------|-------------|
| M1 | **Worst observed** time from page-selection event to complete finding list, over a **named sample of ≥ 5 pages**, each ≤ 150 anchors (a percentile is not computable from a two-page smoke) | ≤ 6s worst observed | T2 exit |
| M2 | Anchor coverage — every anchor in the page HTML appears once in the panel, matched by `href` + document ordinal, **pairwise against an independent DOM query in the canvas** (never the extractor's own output — that compares a component to itself) | 100% | T1 exit |
| M3 | Attribution rate — links whose **structural** `origin` is `content` carrying a working jump-to-field action | ≥ 50% | T3 exit |
| M4 | False positives on a **named known-good control page** in the real-tenant smoke | 0 | T2 exit |
| M5 | UI copy using "broken" / "dead" / "404" / "unreachable" **anywhere, about any link** | 0 occurrences | every `/code-review` |

M4 is deliberate: a sweep that reports failures everywhere is a claim about the checker, not about
the content. M3 is only measurable because `origin` is structural (ADR-0006) — the alternative makes
it 100% by construction.

## 4. Target Users

**Primary — the content editor in Page Builder.** Works inside the canvas, is about to publish, is
not a developer, and has no access to the content tree in the mental model they are using. They need
a verdict and a route to the fix, phrased in their vocabulary ("this link points at a page that isn't
published yet"), not in template/item terms.

**Secondary — the site owner / lead editor.** Cares about the pattern rather than the page: which
chrome links are wrong everywhere because they are wrong once. The rendered-page scope (ledger Q2)
means they will see the same chrome finding on every page — accepted cost, and the reason the
`site chrome` label exists.

**Not a user:** the developer debugging the head app, and the SEO analyst auditing outbound links.
Neither is served by this app and neither should be told otherwise.

## 5. Product Scope

### In Scope

- **Surface:** SitecoreAI Page Builder **context panel**, custom app, our org only — no public
  Marketplace listing, no Sitecore review gate, no submission step (ledger Q1).
- **Page scope:** the **rendered** page as the editor sees it, **including nav and footer chrome**
  (ledger Q2). Accepted cost: some findings are not fixable from the page being viewed.
- **Five checks:**
  1. **Internal target exists** — the link resolves to an item in the CM.
  2. **Unpublished target** — the item exists but is not published to the delivery surface.
  3. **`http://` scheme** — static string inspection, no request issued.
  4. **Malformed or empty `href`** — empty, whitespace-only, unparseable, or a literal placeholder.
  5. **Missing in-page anchor** — `href="#x"` with no `id`/`name` `x` in the page's own HTML.
- **Internal vs external classification** from the tenant's own host list. *Not checked* means
  **reachability** not checked: checks 3 and 4 are string inspection and run on external links
  exactly as on internal ones, and every external row carries a standing *reachability not checked*
  note alongside whatever those checks found.
- **Structural `origin` plus best-effort attribution** — `origin` (`content` | `chrome`) is decided
  by where the anchor sits in the page, independently of whether attribution succeeded. A content
  link mapped to an owning field gets a jump action; a content link whose field cannot be identified
  renders `in your content — field not identified`; a chrome link renders
  `site chrome — not editable from this page`.
- **Two divergent panel designs** at `/design`, one POC winner (`ui_variants: 2`).

### Out of Scope

**Permanently out of scope — architectural, not a backlog item:**

- Every outbound network check: HTTP status (4xx/5xx), redirect chains, DNS failure, TLS validity,
  mixed-content-by-response. Mode A cannot issue the request (ledger Q5).
- Any HEAD proxy, and therefore any concurrency or rate-limit policy for one — moot, there is no proxy.
- Any backing route, server-side surface or OAuth proxy.

**Out of scope for this PRD:**

- Full source attribution for every chrome link — the "keep the promise" option was offered in
  discovery and explicitly not taken.
- Site-wide or multi-page scanning; scheduled or background runs.
- Any write, mutation, publish or redirect-creation action against the tenant.
- Persisted history, trend reporting, export, or telemetry.
- Public Marketplace listing and its interface-guidelines bar (a preference here, not a requirement).

## 6. User Stories

**US-1 — See every link on the page I'm editing.**
*As an editor, I want the panel to list every link on the page I have selected, so that I have one
place to look before publishing.*

- **AC-1.1** Selecting a page in Page Builder populates the panel without a manual refresh.
- **AC-1.2** Every anchor in the rendered page HTML — body, nav and footer — appears exactly once,
  matched by `href` + document ordinal against an independent DOM query in the canvas.
- **AC-1.3** Switching to a different page replaces the list; no findings from the previous page survive.
- **AC-1.4** A page with zero links renders an explicit empty state, not a blank panel.
- **AC-1.5** A row may carry **more than one status**. Every member of its status set is visible on
  the row; the highest-precedence member (§ 10) is the headline and drives sort order. Multiple
  findings never split one anchor into multiple rows.

**US-2 — Know which internal links point at nothing.**
*As an editor, I want internal links whose target does not exist in the CM flagged, so that I don't
publish a link to a page that was never created or has been moved.*

- **AC-2.1** A link resolving to no CM item is flagged as *target not found* with its href shown.
- **AC-2.2** A link resolving to an existing item is not flagged by this check.
- **AC-2.3** When the target cannot be resolved either way (API error, timeout), the link carries
  *could not check* — never silently "fine" and never "not found". `could not check` reports a
  **failed** check and is worded distinctly from *reachability not checked*, which is a **policy**.

**US-3 — Know which links point at a page that isn't published yet.**
*As an editor, I want links to staged-but-unpublished pages flagged distinctly, so that I don't ship
a link that works for me in preview and 404s for a visitor.*

- **AC-3.1** *Unpublished target* is a **distinct** finding class from *target not found*, with its
  own label and its own copy.
- **AC-3.2** The finding names the target page, so the editor can go publish it.
- **AC-3.3** If **T0** proves the endpoint cannot separate the two states (Assumption A2), the merged
  state is labelled honestly as *not found or not published* — it is never presented as one of the
  two when it is actually both.

**US-4 — Be warned about insecure-scheme links.**
*As an editor, I want every `http://` link flagged — internal or external — so that I can correct the
scheme before publishing. This reads the href text and makes no claim about whether the target
responds.*

- **AC-4.1** Any href whose scheme is `http:` is flagged, internal or external.
- **AC-4.2** The check is performed on the string only — no request is issued and no response is
  interpreted.
- **AC-4.3** `https:`, protocol-relative, relative, `mailto:`, `tel:` and `#`-only hrefs are not
  flagged by this check.
- **AC-4.4** An external row flagged `insecure-scheme` **also** carries its standing *reachability
  not checked* note. The two coexist on one row and neither suppresses the other.

**US-5 — Be warned about malformed or empty links.**
*As an editor, I want empty or unparseable hrefs flagged, so that I catch a link that renders as
clickable but goes nowhere.*

- **AC-5.1** Empty, whitespace-only and unparseable hrefs are flagged as *malformed link*, internal
  or external.
- **AC-5.2** The literal placeholders `undefined` and `null` are flagged too. **A bare `#` is
  exempt** — it is the conventional href for JS-driven toggles, accordions and menu triggers, which
  live in exactly the chrome the rendered scope pulls in, so flagging it would put a false finding on
  every page with a menu and make M4's known-good control unreachable (ledger Q4). A bare `#` is
  likewise not evaluated by the in-page anchor check — there is no fragment name to match.
- **AC-5.3** An anchor with no `href` attribute at all is reported, not skipped. Its row identity is
  `(no href)` + document ordinal, so it still occupies exactly one row under AC-1.2.

**US-6 — Know when an in-page anchor has no target.**
*As an editor, I want `#section` links whose target is missing from this page flagged, so that my
jump links actually jump.*

- **AC-6.1** `href="#x"` with no element carrying `id="x"` or `name="x"` in the page HTML is flagged.
- **AC-6.2** A matching target anywhere in the page — including chrome — satisfies the check.
- **AC-6.3** The check runs against the page's own HTML only; a `#`-fragment on a link to a
  *different* page is not evaluated.
- **AC-6.4** If **T0** proves the page-HTML endpoint returns layout JSON rather than rendered HTML
  (Assumption A1), this story is **withdrawn**, not approximated — an in-page anchor check is never
  simulated from layout, and the row-identity and scope consequences go back to the operator before
  T1 opens.

**US-7 — Get to the field, or be told plainly why I can't.**
*As an editor, I want a jump action on findings I can fix here and an honest label on the ones I
can't, so that I stop looking instead of hunting for a field that isn't on this page.*

- **AC-7.1** A link attributed to an owning field renders a jump action that selects that field in
  the canvas.
- **AC-7.2** A link whose structural `origin` is `chrome` renders the exact string
  `site chrome — not editable from this page` and **no** jump action.
- **AC-7.3** A link whose structural `origin` is `content` but whose owning field could not be
  identified renders the exact string `in your content — field not identified` and no jump action.
  It **must never** render the chrome string — that would be a false statement about where the link
  lives, and § 2's premise is that a misleading panel is worse than no panel.
- **AC-7.4** No finding renders a jump action that does not resolve to a selectable field.
- **AC-7.5** The three-way split — jumpable / content-but-unidentified / chrome — is visible at a
  glance without opening each finding.

**US-8 — Understand what this app does not check.**
*As an editor, I want the panel to be explicit that no link's reachability is verified, so that I
don't infer coverage the app cannot provide.*

- **AC-8.1** Every external link is listed, string-checked, and carries a visible standing
  *reachability not checked* note (exact copy set at `/design`), worded distinctly from *could not
  check*.
- **AC-8.2** No UI copy uses "broken", "dead", "404" or "unreachable" **anywhere, about any link**.
  The ban is global, not external-only.
- **AC-8.3** The panel states its scope — internal link integrity, no reachability — somewhere
  permanently visible, not only in a dismissible first-run message.

## 7. Functional Requirements

**Acquisition and lifecycle**

- **FR-1** Subscribe to `pages.context` and recompute the finding list on every page-selection change.
- **FR-2** Retrieve the current page's rendered HTML via the page-HTML endpoint and extract every
  anchor with its href and document ordinal. *(Shape unverified — see Assumption A1.)*
- **FR-3** Read `application.context` for app identity/host wiring at init.
- **FR-4** Discard all state on page change; hold nothing across a reload.

**Classification**

- **FR-5** Retrieve the tenant's site host list via `xmc.sites.*` and classify each link's `scope`.
  A relative href is `internal`. A protocol-relative `//host/x` is resolved against the host list
  exactly like an absolute URL. `mailto:`, `tel:` and `javascript:` are `non-navigational` — they sit
  on neither side of the axis and are exempt from resolution, scheme and anchor checks. Anything else
  matching no known host is `external`.
- **FR-6** Resolve each internal link via `path-by-url` and classify as *exists* / *not found* /
  *exists-but-unpublished*. *(The third depends on Assumption A2.)*
- **FR-7** Flag `http:`-scheme hrefs by string inspection, internal **and** external.
- **FR-8** Flag empty, whitespace-only, unparseable and placeholder (`undefined`, `null`) hrefs,
  internal **and** external. A bare `#` is exempt (AC-5.2).
- **FR-9** Flag `#`-fragment links with no matching `id`/`name` in the page HTML.
- **FR-10** Represent an unresolvable check as an explicit `could-not-check` — never as a pass, and
  worded distinctly from the `reachability-not-checked` policy note.
- **FR-11** Apply FR-7 and FR-8 to external links exactly as to internal ones, and attach the
  standing `reachability-not-checked` note to every external row. **No** external link is resolved,
  requested or reachability-classified.
- **FR-12** Represent a link's classification as a **set** of statuses, not a single value; render
  every member on the row with the highest-precedence member as the headline (§ 10). One anchor is
  always exactly one row.

**Attribution and presentation**

- **FR-13** Determine `origin` (`content` | `chrome`) **structurally**, from where the anchor sits in
  the page, before and independently of attribution. An attribution failure never changes `origin`.
  *(Rests on Assumption A4 — T0 probe question (f).)*
- **FR-14** Best-effort map each link to an owning field; expose a jump action where the mapping
  resolves to a selectable field.
- **FR-15** Render exactly one of three affordances per link: a jump action (attributed content
  link) · `in your content — field not identified` (content link, no owning field) ·
  `site chrome — not editable from this page` (chrome link). The latter two carry no jump action, and
  the chrome string is never applied to a `content` link.
- **FR-16** Group and order findings so the fixable-here set is reachable without scrolling past the
  chrome set (exact grouping decided at `/design`).
- **FR-17** Render distinct empty, loading and error states.

**Prohibitions (testable)**

- **FR-18** The app issues **no** network request to any link target. Any `fetch`/`XHR`/`HEAD` against
  an extracted href is a defect.
- **FR-19** The app performs **no** write, mutation or publish against the tenant.

## 8. Non-Functional Requirements

- **NFR-1 Performance** — M1's budget (worst observed ≤ 6s over a named ≥ 5-page sample, each ≤ 150
  anchors). Resolution calls are de-duplicated by target path; the same href appearing 20 times costs
  one lookup.
- **NFR-2 Partial results over blank** — if one classification source fails, findings from the others
  still render, with the failed class marked `could-not-check`. The panel never blanks because one
  call failed.
- **NFR-3 Read-only and side-effect-free** — no writes, no persistence, no telemetry, no cookies.
- **NFR-4 Panel fit** — usable at the context panel's actual width without horizontal scrolling;
  long hrefs truncate with the distinguishing end visible. A multi-status row must stay scannable at
  that width.
- **NFR-5 Accessibility** — keyboard-reachable findings and jump actions; findings are not conveyed
  by colour alone. Blok interface guidelines are a **preference** here, not a gate (ledger Q1).
- **NFR-6 Honesty of copy** — the global word ban, enforced as M5 at every `/code-review`.

## 10. Data Model Overview

The app **creates no Sitecore templates, items or fields** and persists nothing. The only model is an
in-memory, per-page-selection structure:

- **`LinkFinding`** — `href` (raw, as authored; `(no href)` where the attribute is absent) ·
  `ordinal` (document position; `href` + `ordinal` is the row identity) · `scope`
  (`internal` | `external` | `non-navigational`) · `origin` (`content` | `chrome`, determined
  **structurally** from where the anchor sits, never from attribution success) · `statuses` (a
  **set**, not a single value) · `severity` · `attribution` (owning field reference, or null) ·
  `targetLabel` (resolved page name, when known).
- **Status set members** — `ok` · `not-found` · `unpublished` · `not-found-or-unpublished` ·
  `malformed` · `insecure-scheme` · `missing-anchor` · `could-not-check` (a check **failed**) ·
  `reachability-not-checked` (**policy**; stands on every `external` row and is never removable).
- **Display precedence**, headline first: `not-found` → `not-found-or-unpublished` → `unpublished` →
  `malformed` → `missing-anchor` → `insecure-scheme` → `could-not-check` → `ok`.
  `reachability-not-checked` is never a headline and is never suppressed. Precedence decides the
  headline and the sort **only** — every member of the set stays visible on the row, which is what
  keeps `could-not-check` from being hidden behind a louder finding (AC-2.3).
- **`PageScan`** — the page identity from `pages.context`, the ordered `LinkFinding[]`, per-source
  health flags backing NFR-2, and a completion timestamp.

`not-found-or-unpublished` exists only as the honest merged state if Assumption A2 is refuted; if T0
confirms the distinction, it is never emitted. Field names above are indicative — the real shapes are
constrained by the T0 fixtures.

## 11. UX Considerations

- **Surface constraints.** The context panel is narrow and vertical, inside the Page Builder canvas.
  Findings must be scannable at a glance; the panel competes with the page for the editor's attention
  and loses if it needs study. A multi-status row raises the bar rather than lowering it.
- **The honest-boundary problem is a UX problem.** The scope statement (AC-8.3) has to be permanently
  visible without dominating the panel — this is one of the things the two `/design` variants should
  diverge on.
- **Two divergent proposals** (`ui_variants: 2`), one POC winner, and the `design` gate is the single
  operator stop in this run. Suggested axis of divergence: *grouped by severity* (worst first,
  chrome folded away) vs *grouped by fixability* (fixable-here first, chrome as a labelled tail).
- **Both fixed label strings are load-bearing.** Each must read as an answer, not a disabled button,
  and the two must be distinguishable at a glance (AC-7.5) — they imply different next steps.
- **States:** empty (no links), loading (page changed, results pending), partial (NFR-2), error.
  Loading must not look like "clean".
- **T3** closes with a **pixel compare against the POC winner** — the POC is the implementation
  contract for the visual layer, not a mood board.

## Amendment — AC-7.1 and AC-7.4 superseded (2026-09-01, ADR-0010)

The T0 probe established at runtime that **field-level selection does not exist**: the client exposes
exactly `["pages.reloadCanvas", "pages.context"]` for mutation, `getValue` is not implemented, and
`PagesContextParams` is `{ itemId?, language?, itemVersion? }`. Item-level navigation succeeds.

**AC-7.1** ("selects that field in the canvas") and **AC-7.4** ("no jump action that does not resolve
to a selectable field") therefore describe a capability the platform does not offer, and are
**superseded by ADR-0010**:

- **AC-7.1 (amended)** — for an attributed `content` link, the panel names the owning rendering and
  datasource (from `pages.context`'s `presentationDetails`) and offers a control that navigates to
  **that item**, labelled for what it does. Never "jump to field".
- **AC-7.4 (amended, and stronger)** — **no control may promise a resolution the platform cannot
  perform.** Where the owner cannot be determined, the finding keeps the
  `in your content — field not identified` label and offers no control at all.
- **M3 (clarified)** — counts links carrying a working **owner-and-open** control. The ≥50% threshold
  is unchanged; what changed is that it now measures something achievable.

Recorded here rather than only in the ADR so the spec and the build do not diverge — the run's own
`/challenge-prd` found two blockers caused by exactly that gap.

## Amendment 2 — AC-7.1 corrected: navigate to the target PAGE, not the owning datasource (2026-09-02, ADR-0010 amended)

**Live defect (operator-reported, CRITICAL):** the shipped "Open in canvas" control navigated to the
**owning datasource item** (`attribute()`'s `target.itemId`, sourced from `presentationDetails`'
`dataSource` field) via `client.mutate('pages.context', { itemId })`. A datasource is not a page;
`pages.context` cannot open one, and clicking the control produced an error page in the live portal.
This was Amendment 1's own mechanism shipped wrong — the T0 probe verified `pages.context` against
the *current page's own id* (a page), and passing a datasource id was never exercised before ship.

**Correction:** the panel already resolves every internal link's **target page** as part of TR-4
(`resolveInternal`, ADR-0009 call 1) — that item id (`LinkFinding.targetItemId`) is a genuine page and
is what the control now navigates to. The **owner label** (rendering + datasource, from
`attribute()`) stays exactly as Amendment 1 described, but as **text only** — it tells the editor
*where the link lives*, not where the control goes.

- **AC-7.1 (amended again)** — the owner-and-open control navigates to the link's **resolved target
  page** (`targetItemId`), never to the owning datasource. It renders whenever a target page was
  resolved — independently of whether the owning rendering/datasource could be attributed at all (the
  two signals are now separate; an unattributed content link with a resolved target still gets the
  control, labelled generically).
- **AC-7.4 (unchanged in force)** — still no control may promise a resolution the platform cannot
  perform; this correction is exactly that principle applied to the earlier fix.
- **M3 (re-clarified)** — the numerator now counts content-origin findings with a non-null
  `targetItemId` (what the control actually renders for), not structural attribution success. See
  `lib/scan/attributionRate.ts`.

Full mechanism, code pointers and the clean-state UI defect fixed in the same pass:
`docs/build-decisions.md`.
